# 🎰 NovaBet — Provably Fair Crypto Casino MVP

Репозиторий содержит децентрализованное приложение (dApp) крипто-казино (игра Coin Flip), построенное на базе передовых стандартов Web3-разработки, компонентной архитектуры и премиального UI/UX.

## 🟢 Что работает (Current Functionality)

На текущий момент приложение полностью функционально и готово к продакшн-релизу в тестовой сети:

- **Интеграция с MetaMask:** Реализовано полноценное подключение кошелька через `ethers.js v6`, динамический опрос баланса пользователя в ETH, а также чтение внутренних балансов смарт-контракта напрямую из блокчейна Sepolia.
- **Реактивный стейт-менеджмент:** Архитектура построена на базе **Pinia Stores**, обеспечивающих мгновенную синхронизацию данных между изолированными компонентами UI.
- **Полноценный игровой цикл (On-Chain Loop):** Функции внесения депозита (`deposit()`), вывода (`withdraw()`) и ставки (`flip()`) отправляют реальные транзакции в сеть Sepolia. Результат игры парсится асинхронно из логов транзакции (`Transaction Receipt` -> событие `CoinFlipped`).
- **Защита от Edge-кейсов (Сети и Аккаунты):** Разработан интеллектуальный баннер `WrongNetworkBanner.vue`, блокирующий интерфейс при неверной сети (требуется Sepolia, ChainID `11155111`) с возможностью автоматического переключения в один клик. Настроены слушатели `accountsChanged` и `chainChanged`.
- **Доказуемая честность (Provably Fair):** В интерфейс встроен интерактивный разбор формулы генерации случайных чисел на основе хэшей блоков, а в модальное окно результатов и историю игр интегрированы прямые ссылки на **Etherscan** для верификации логов.
- **Интеллектуальная локализация ошибок:** Добавлен продвинутый перехват внутренних исключений `ethers.js`/MetaMask (таких как активный запрос подключения `-32002` или отказ от транзакции `ACTION_REJECTED`) с их переводом на понятный пользователю язык.
- **Премиальный UI/UX и Локализация:** Интерфейс выполнен в киберпанк-стилистике на базе **Tailwind CSS v4** с использованием шрифта _Outfit_, анимированных 3D-переходов, нативных `.wav` звуковых эффектов для дофаминового отклика и полной поддержкой **RU / EN** языков.

## 🔴 Что не работает (Known Limitations / Scope)

- **Поддержка мобильных кошельков (WalletConnect / Deep Links):** В рамках 48-часового MVP интеграция была сфокусирована исключительно на расширении MetaMask (Injected Provider) для десктопных браузеров. Мобильный флоу через WalletConnect / внутренние браузеры кошельков временно не поддерживается.
- **Логирование отмененных блоков (Chain Reorgs):** Если сеть Sepolia столкнется с реоргом блоков в момент ожидания транзакции, фронтенд может некорректно отобразить застрявший статус `isPending`. В мейннете для этого требуется интеграция индексаторов (например, The Graph).

## 💎 Почему был выбран именно Ethereum (а не Solana)?

Выбор **Ethereum экосистемы (Solidity)** для данного проекта был продиктован следующими инженерными и продуктовыми соображениями:

1. **Индустриальный стандарт безопасности iGaming:** Язык Solidity и виртуальная машина EVM предоставляют проверенные годами паттерны проектирования смарт-контрактов для азартных игр. В частности, паттерн _Check-Effects-Interactions (CEI)_, примененный в нашем контракте `Casino.sol`, гарантирует математическую защиту от атак повторного входа (Reentrancy), что критично для систем с мгновенными выплатами.
2. **Детерминированный аудит через логи:** Архитектура событий EVM (`Events / Logs`) идеально подходит для реализации концепции _Provably Fair_. Генерация лога `CoinFlipped` позволяет фронтенду легко и дешево парсить результаты, а игроку — верифицировать их через стандартный Etherscan без необходимости разбора сложных структур аккаунтов, как это устроено в модели данных Solana (Anchor/Sealevel).
3. **Скорость прототипирования инфраструктуры:** Наличие таких инструментов, как Remix IDE и `ethers.js`, позволило развернуть, протестировать и связать смарт-контракт с фронтендом в кратчайшие сроки, сфокусировавшись на полировке UX.

## 🧠 Самая сложная задача, которую удалось решить (The Hardest Unknown)

### Проблема: Конфликт Прокси Vue 3 и приватных полей классов `ethers.js` (Ошибка `#notReady`)

На этапе интеграции реального MetaMask столкнулся с критическим и трудноотлаживаемым багом во Vue 3. При попытке сохранить объекты `BrowserProvider`, `Signer` или `Contract` в стандартные реактивные переменные Pinia через `ref()` или `reactive()`, Vue оборачивал эти тяжелые ES6-классы в глубокие прокси-объекты (`Reactive Proxy`).

Это приводило к тому, что при любой попытке вызвать метод контракта (например, `contract.value.flip()`) внутренний код `ethers.js` пытался обратиться к своим приватным свойствам (начинающимся с символа `#`, таким как `#notReady`). Proxy-оболочка Vue 3 блокировала доступ к приватным членам класса, вызывая падение приложения с системной ошибкой: `TypeError: Cannot read private member from an object whose class did not declare it`.

### Решение: Оптимизация реактивности через `shallowRef`

Для решения этой проблемы была применена низкоуровневая оптимизация стейта Vue. Все тяжелые сущности Web3-окружения были переведены на использование **`shallowRef()`** вместо стандартного `ref()`:

```javascript
const provider = shallowRef(null)
const signer = shallowRef(null)
const contract = shallowRef(null)
```

`shallowRef` делает реактивной только саму ссылку на объект, но не пытается проксировать его внутренности. Это полностью устранило конфликт с приватными свойствами `ethers.js`, сохранив высокую производительность фронтенда и реактивность интерфейса на изменение состояния подключения.

## 🚀 Что бы я создал дальше (Roadmap)

Я бы развивал проект в следующих направлениях:

1. **Chainlink VRF (Verifiable Random Function):** Текущая генерация случайности на основе `blockhash` и `timestamp` безопасна для уровня тестнета, но уязвима к манипуляциям со стороны майнеров/валидаторов в промышленных масштабах (MEV-атаки). Интеграция Chainlink VRF обеспечит математически доказуемую, криптографически защищенную случайность, генерируемую вне сети.
2. **Account Abstraction (EIP-4337) & Gasless Transactions:** iGaming-индустрия требует отсутствия трения при входе. Я бы внедрил спонсируемые транзакции (Paymasters), чтобы казино оплачивало газ за пользователя, а сам игрок мог авторизоваться через Google / Apple ID и играть без необходимости вручную устанавливать MetaMask и покупать Sepolia ETH.
3. **Расширение игровой линейки (Dice, Crash):** Благодаря созданной компонентной архитектуре и изолированному Pinia-стору, добавление новых механик (например, многопользовательского Crash-графика) потребует лишь написания нового UI-компонента и пары методов в контракте, не затрагивая ядро системы.
